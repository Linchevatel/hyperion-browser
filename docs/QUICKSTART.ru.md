# Быстрый старт и инструкции по сборке

[English](QUICKSTART.md) · [README](../README.ru.md) · [FAQ](FAQ.ru.md)

## Готовые пакеты (рекомендуемый первый шаг)

Скачайте доступный файл для своей ОС и архитектуры из [GitHub Releases](https://github.com/Linchevatel/hyperion-browser/releases). Сведения о движке — в [FAQ](FAQ.ru.md#какой-движок-используется).

- **Linux AppImage:** замените пример имени ниже на имя скачанного файла. Дистрибутиву может требоваться поддержка FUSE; следуйте его рекомендациям по AppImage, а не отключайте sandbox.
  ```bash
  chmod +x ./Hyperion-Browser-VERSION.AppImage
  ./Hyperion-Browser-VERSION.AppImage
  ```
- **Debian/Ubuntu:** `sudo apt install ./DOWNLOADED_FILE.deb`
- **RPM-дистрибутивы:** используйте свой пакетный менеджер, например `sudo dnf install ./DOWNLOADED_FILE.rpm` в Fedora.
- **Windows:** запустите установщик или портативный исполняемый файл. Для работы с cookies и прогрева Python 3 должен быть доступен как `python`, `py` или `python3`.

Запускайте приложение/браузер от обычного пользователя. Текущий процесс выпуска упаковывает Linux и Windows; это не подтверждает совместимость со всеми дистрибутивами и не предоставляет релизы macOS.

## Первый профиль

1. Откройте настройки и проверьте путь к исполняемому файлу браузера. При необходимости выберите доверенный модифицированный Chromium; сохранённый существующий путь имеет приоритет над автопоиском.
2. Создайте пробный профиль. Выберите ОС профиля и проверьте конфигурацию отпечатка. Это набор настроек, а не эмулятор ОС.
3. Если нужен прокси, укажите протокол, адрес, порт и при необходимости данные авторизации, включите его и выполните проверку соединения. Прокси приобретаются отдельно.
4. Запустите профиль. Проверьте внешний IP, поведение WebRTC/DNS и свойства браузера в своём тестовом окружении. Успешная проверка прокси не является полной проверкой утечек.
5. Остановите профиль перед импортом/экспортом cookies или копированием данных. Не запускайте прогрев для профиля, уже открытого в браузере.

## Запуск из исходников

Нужны Git и актуальная среда Node.js/npm; процесс выпуска использует **Node.js 22**. Electron требует графический рабочий стол и системные библиотеки. Python 3 нужен для операций с cookies и прогрева; эти скрипты используют стандартную библиотеку Python.

```bash
git clone https://github.com/Linchevatel/hyperion-browser.git
cd hyperion-browser
npm ci
npm start
```

В Linux после установки зависимостей можно также использовать `./hyperion-app`. Это shell-обёртка, а не готовый установщик.

Настольный клиент и движок Chromium — отдельные компоненты. Если подходящего движка нет, его можно скачать:

```bash
npm run download:engine
# Явная цель Windows x64 (для упаковки Windows):
node scripts/download_engine.js --platform=win64
```

**Читайте вывод загрузчика.** Он ищет модифицированный движок в релизах `chromium-core-*`, затем переходит на ungoogled-chromium без патчей. Он скачивает/распаковывает исполняемые файлы в `bundle/chrome`; запускайте его только при доверии к источникам. Для компиляции движка используйте раздел сборки ниже. Системный Chrome/Chromium может запускать профили, но не реализует специальные ключи отпечатка.

## Упаковка настольного клиента

```bash
npm run dist:linux  # AppImage, deb, rpm
npm run dist:win    # установщик NSIS и портативный exe
```

Результат появляется в `dist/`; имена/версии зависят от сборки. Эти команды **упаковывают существующий каталог `bundle/chrome`, а не компилируют и не скачивают Chromium**. Сначала подготовьте полный комплект движка для целевой ОС. Для RPM нужны соответствующие инструменты; кросс-сборка Windows может требовать дополнительных инструментов electron-builder. Актуальные настройки — в [package.json](../package.json) и [процессе выпуска](../.github/workflows/build-and-release.yml).

## Сборка модифицированного Chromium (для опытных пользователей)

Следуйте [инструкции Chromium для Linux](https://chromium.googlesource.com/chromium/src/+/main/docs/linux/build_instructions.md) для подготовки системы, depot_tools, исходников и зависимостей. Это отдельная ресурсоёмкая сборка, не часть `npm ci`.

1. Синхронизируйте Chromium с целевой ревизией из [`CHROMIUM_VERSION`](../CHROMIUM_VERSION), удалив суффикс упаковки после `-`, если он есть, затем выполните hooks. Не применяйте патчи к произвольной свежей версии upstream.
2. В чистом checkout Chromium `src` проверьте и примените патчи **по порядку**, заменив `/absolute/path/hyperion-browser` ниже:
   ```bash
   git apply --check /absolute/path/hyperion-browser/patches/hyperion_core_fingerprint.patch
   git apply /absolute/path/hyperion-browser/patches/hyperion_core_fingerprint.patch
   git apply --check /absolute/path/hyperion-browser/patches/hyperion_webgl_presets.patch
   git apply /absolute/path/hyperion-browser/patches/hyperion_webgl_presets.patch
   ```
3. Изучите конфигурацию GN в процессе выпуска, сгенерируйте `out/Release` и соберите через `autoninja -C out/Release chrome`. Параметры и совместимость патчей меняются вместе с Chromium; при ошибке проверки остановитесь и выясните причину.
4. Подготовьте комплект из исполняемого файла **и ресурсов для его работы**, включая locales, `.pak`, данные ICU/V8 и нужные разделяемые библиотеки, как в процессе выпуска. Копирования только `chrome` недостаточно. Используйте `bundle/chrome` для упаковки клиента или выберите исполняемый файл в настройках для локального запуска.

Процесс выпуска Linux проверяет патчи и собирает модифицированный движок. Windows использует загрузчик движка.

## Решение проблем и сообщения об ошибках

- **Браузер не найден:** проверьте настройки, права исполнения и нужные библиотеки браузера. Выбор обычного Chrome решает поиск, но не добавляет поддержку специальных настроек отпечатка.
- **Ошибка запуска/AppImage:** запустите из терминала для получения короткого сообщения об ошибке; изучите требования Electron/AppImage своего дистрибутива. Не используйте root и не отключайте sandbox как универсальное решение.
- **Ошибка прокси:** самостоятельно проверьте протокол, включение и данные авторизации. Обычный запуск и прогрев используют разные пути авторизации.
- **Сообщение об ошибке:** укажите ОС/архитектуру, версию приложения, фактическую версию/путь движка (без личных данных), источник установки, шаги, ожидаемый/фактический результат и очищенные фрагменты ошибок в [форме issue](https://github.com/Linchevatel/hyperion-browser/issues/new/choose). Не прикладывайте токены, cookies, данные авторизации прокси или полные профили.
